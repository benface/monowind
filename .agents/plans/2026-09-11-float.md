# Float implementation plan

Status: **done** (2026-09-11; all four phases, the native agreement
probed in three engines — spec "Browser agreement"). Spec:
`.agents/specs/float.md` (normative; this plan only sequences it).

## Phases (each ends green: `pnpm check` + the visual sweep)

### 1. Style and tree

- `style.ts`: read `float` and `clear` onto `CellStyle`, `float`
  forced to `none` on an out-of-flow box as CSS computes it.
- `tree.ts` `childRole`: a floated element is `block`, so a floated
  `<span>` leaves its text run and the text around it becomes anonymous
  runs (the machinery already there).
- Node tests: the reads, the forcing, a floated inline out of its run.

### 2. Layout

- `wrap.ts`: `WrapOptions.openLine(index, closed)` (the spec's
  protocol) replaces the `bandWidth` hook phase 1 left there. The
  wrapper keeps ONE flat span list across hard lines (`wrapLineSpans`
  hands its array into `wrapHardLine` instead of concatenating), so
  `closed` is every line before this one; the callback returns the
  line's usable width (layout's opener records the row and x it chose
  as the leaf's `lineBands`), and the line takes that width minus its
  indent. Without the callback a line has the full width and the rows
  are contiguous, as today.
- `layout.ts` `layoutNode`: an optional `intrusions` argument —
  `{ boxes, contentWidth, x, y }`: the container's float boxes and
  content width, and the child's border-box origin in the container's
  content box — threaded to the leaf branch, which builds `openLine`
  from them: line `index`'s row is the previous lines' rows plus
  heights (`leafLineMetrics` over `closed`, so a tall inline box
  counts), moved down while `bandAt` at `y + border.top + padding.top +
row` has no width; the band comes back clipped to the leaf's own
  content box, in its coordinates. Only a text leaf receives
  intrusions (deviation 2).
- `layout.ts` `layoutBlock`: place children in document order against a
  running float context. Each in-flow child's top is resolved before
  its layout (margins collapsed, then the `clear` max). A LEAF child is
  laid out at that top with `intrusions` (its x its left margin, an
  `auto` margin as 0; a child whose cross offset comes out different
  once its width is known — an auto-margin-centered leaf beside a
  float — is laid out once more with the corrected x, then stable). A
  CONTAINER child is laid out first, then placed as a BFC root with
  `placeFloat`'s search (shared: the first row from its top whose band
  holds its margin box, x at the band's start plus its left margin).
  A float is laid out shrink-to-fit against the content width, placed
  by `placeFloat` (its `clear` applied to its top first), added to the
  context, and skipped by the block cursor and by margin collapsing;
  the container's content height is the larger of the cursor and
  `floatsBottom`. `placeFlowChildren` runs when the container holds
  anonymous runs OR floats, passes floats by, writes a container
  child's left margin relative to the band at its row, and gives a
  float its own authored margins resolved to cells.
- `layout.ts` `leafLineGeometry`: the opportunity rows become `lineY`
  (and `totalRows` the last row plus its height), the bands the leaf's
  `lineBands`; the atomic-box placement in the leaf branch adds the
  line's band x as it adds multicol's `lineX`.
- `plain-text.ts` `forEachLeafCell`: a line's x adds `lineBands[i].x`,
  and its alignment and truncation width is `lineBands[i].width` — so
  the paint, `charIndexAtCell`, `inlineElementRects`, and the
  transcript follow at once.
- `multicol.ts`: a floated direct child is laid out as a plain column
  item and warned once (deviation 1).
- `borders.ts` `paintOrderedChildren`: the floats bucket between the
  in-flow blocks and the inline boxes.
- Intrinsic widths (`intrinsicOuterWidth` / `minContentOuterWidth` for
  a block container): a float's outer width sums into max-content
  beside its text and takes the max for min-content.
- Node tests: the spec's Testing list, plus `renderPlainText`; a
  `floats.test.ts` for `floats.ts` on its own.

### 3. Native flow

- `render.ts`: `data-mw-float="left|right"` (the side in the value)
  with `--mw-mt/mr/mb/ml` from the node's `flow` margins, no
  `data-mw-laid-out`; the container's other in-flow children arrive
  as `data-mw-flow` children through the same `flow` field a mixed
  container's already use, the value `"box"` for a container and
  `"text"` for a leaf.
- `styles.css`: `[data-mw-float="left"]` / `[data-mw-float="right"]` —
  `float`, `position: static`, the shared geometry rule, the flow
  margins and translate — beside the flow-child rule; `contain: layout`
  moves from `[data-mw-flow]` to `[data-mw-flow="box"]`, so a leaf's
  line boxes shorten natively while a container steps aside.
- The anonymous-runs stories keep passing: their flow-child containers
  keep containment, and the host story's nested-margin case is a
  container.
- Storybook (`Test / Host` neighbours and a visible story): the
  browser's line boxes over the engine's rows for every wrapped line.

### 4. Stories, docs, playground

- A visible `Features / Float` story: a drop cap, a right float, two
  floats side by side, a `clear-left` block; its golden in the sweep.
- Docs: cell-model.md, positioning.md, multicol.md, README per the
  spec's touch points.
- The playground sample gets its drop cap.
