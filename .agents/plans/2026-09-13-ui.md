# `@monowind/ui` implementation plan

Status: **implemented** (2026-09-13, phase 7 on 2026-09-18; every
phase green, the four goldens recorded). Spec: `ui.md` — normative;
`anchor-positioning.md` for the placement it relies on, `top-layer.md`
for the layer its floating parts live in, `animations.md` for the
enters and exits, `focus-navigation.md` and `cell-model.md` for the
engine's keyboard and pointer rules it meets; this plan only sequences
them. Phase 3 of `2026-09-13-components.md`.

## Shape

Four things are new: a package with one entry per component, a
per-component core — `props(p)`, the machine's props with the grid's
positioning options, and `api(zagApi, normalizeProps, p)`, Zag's
connected API with the grid's props on the trigger and the positioner
— one DOM effect
(`syncTopLayer`) that keeps the positioner shown as a popover from
the machine's open through its exit, and a vanilla path that mounts
a machine on markup marked with `data-part`. The engine is used as it
is, plus two rules it lacks: ARIA widget roles among the elements
that take pointer events in grid mode, and among those whose arrow
keys are their own under `focus="arrows"`.

The props are inline styles and attributes Zag's `normalizeProps`
already carries — `style.anchorName`, `style.positionAnchor`,
`style.positionArea`, `style.positionTryFallbacks`, a margin in cells
for the gutter, `popover: "manual"` — so a framework spreads them like
any Zag prop, and the engine reads them as computed values. The anchor
name is `--mw-ui-` plus the machine's `id`, its non-ident characters
(React's `:r0:` colons) replaced by `-`. The content's `hidden`,
Zag's, is dropped: a closed manual popover is the UA's to hide, after
its exit.

## Phases (each ends green: `pnpm check`, `pnpm test`, the visual sweep)

### 0. Probe

A temporary `zz-probe` package test and story, deleted after, on Zag
1.44: what `getPositionerProps()` and `getItemProps()` emit (a `hidden`
while closed, a `tabindex` on items, `data-placement`, any `style`
left to override) and which positioning options stop floating-ui's
listeners; whether a Zag menu mounts and opens under happy-dom (else
the package's tests run in vitest's browser mode, as the stories do);
in the three engines and both select modes: a pointer click on the
trigger opening the menu, a pointer move highlighting an item, the
arrow keys inside an open menu moving the highlight under
`focus="arrows"`, Escape closing it, an outside click on the grid
closing it (Zag's dismissal reads `composedPath`); what
`getTriggerItemProps` returns for a nested menu, and which element is
the child's anchor.

### 1. The package

- `packages/ui`: `package.json` modeled on `@monowind/vite` (no
  stylesheet): `exports` `./menu`, `./dialog`, `./popover`,
  `./tooltip`, `./package.json`, the `typecheck` → `types` swap in
  `publishConfig`, `sideEffects: false`; `dependencies` on
  `@zag-js/core`, `@zag-js/vanilla`, `@zag-js/types`, and the four
  machines at 1.44.0; `devDependencies` on `@zag-js/react`, `react`,
  `react-dom`, `@types/react`, `happy-dom`, `vite`, `vitest`,
  `typescript`; version `0.2.14` until the milestone's bump.
- `vite.config.ts`: a library build with one entry per subpath
  (`dist/menu.js`, …, the shared chunks beside them), Zag external;
  `tsconfig.build.json` for the declarations; `vite.cdn.config.ts` an
  IIFE `dist/cdn.js` bundling Zag, `monowind.ui.{menu,dialog,popover,
tooltip}` on the shared global for the playground and classic scripts.
- `README.md`: the package's opening, setup per integration, one
  example per component (styled through the theme tokens), the parts
  and states.

### 2. The engine's two rules

- element.ts `INTERACTIVE` and the `styles.css` rule it mirrors (one
  rule since 2026-09-18, a test holding the two equal): the ARIA
  widget roles join the list — `role="button"`,
  `menuitem*`, `option`, `tab`, `treeitem`, `checkbox`, `radio`,
  `switch`, `slider`, `link`, `combobox` — so a component's parts take
  pointer events in grid mode as buttons do. Found 2026-09-19: the
  containers (`menu`, `listbox`, `tablist`) are focusable with a
  `tabindex` of 0, so ARIA's composite roles leave the list (their
  cells are the grid's, their items the widgets), and the focus invert
  skips them (their highlighted item is the indication; Zag's
  `aria-activedescendant` comes and goes with the highlight, so the
  role is the key) — `COMPOSITE` in element.ts.
- element.ts `#onKeyDown`: an arrow key a handler cancelled stays
  handled — the host's navigation yields to `defaultPrevented`, the
  general rule every ARIA widget meets.
- Stories for both (a widget's items hovered and clicked over the
  grid; a widget keeping its arrows under `focus="arrows"`);
  `cell-model.md` (grid mode's interactive elements) and
  `focus-navigation.md` amended.

## Probe findings (2026-09-13)

- Zag installs at 1.43.3: 1.44.0 shipped the same day and the
  workspace's release-age gate holds it for a day; bumped to 1.44.0
  once it matured.
- Zag's `hidden` rides on the content, not the positioner; the
  positioner's inline style is all Zag's own positioning
  (`position: absolute; isolation; min-width: max-content;
pointer-events: none; top; left; transform: translate3d(0, -100vh,
0); z-index`), which the core replaces with its own (the
  `min-width: max-content` kept, so a menu stays one width and flips
  rather than wraps). `PositioningOptions` has `applyStyles`, `flip`,
  and `listeners`; the core sets all three off.
- Under happy-dom a Zag menu mounts and opens (its transition settles
  a tick later), so the package's tests stay in node.
- With real input in the three engines, text mode: click opens, hover
  highlights, arrows move the highlight and stop at the ends, Escape
  closes and restores focus, a click on the grid or another button
  closes; `focus="arrows"` never took an arrow from the open menu.
  Grid mode: the same, except items had no pointer events (the first
  engine rule). Testing-library's `hover` reaches no Zag handler in
  any mode (its pointer events carry no `pointerType`); stories hover
  with vitest's browser `userEvent` or a dispatched `PointerEvent` of
  `pointerType: "mouse"`.
- Chromium applies `position-try-fallbacks` natively while the engine
  reads, from its pixel geometry, and reports the fallback it chose as
  the computed `position-area` (a tooltip above a button 1rem from the
  top read as `bottom`); the engine now scopes every anchor name to its
  subtree under `[measuring]`, so nothing resolves natively during the
  read. The positioner's UA `overflow: auto` made it a scroll container
  that clipped instead of overflowing, defeating the fit test; the core
  sets `overflow: visible` on it.
- The stories live in one file, `ui.stories.ts`, under `Packages / ui`
  beside `ascii` and `qr-code`, a story per component, their goldens
  `packages-ui--*`.
- `@zag-js/solid` reaches `solid-js/web` (through
  `@solid-primitives/keyed`), which Solid 2.0 RC no longer exports:
  the Solid example keeps its counter until the adapter follows; React
  and Svelte carry the menu and the dialog.
- `getTriggerItemProps(child)` returns the child's trigger props with
  `role="menuitem"` and the child's `data-uid`, so the anchor name of
  any trigger derives from its own `data-uid` and a positioner's from
  its `id` (`menu:<uid>:popper`). Those props change with the child —
  its link to the parent (a `send`, which the vanilla machine runs a
  microtask later) and its open state — so the vanilla mount of a menu
  follows its submenus' machines as well as its own, and spreads first
  a microtask after the mount, the links made: a spread before them
  named the trigger item a plain `trigger`, which a mount right after a
  destroy on the same markup (Lit's `ref` disconnects and reconnects
  the story's tree when Storybook re-renders it for a toolbar change)
  could no longer find; and the spread writes the child's trigger id as
  the item's `data-value`, so a submenu root pairs with the trigger item
  it follows, its own `data-value` naming the submenu.
- Zag's dialog and popover content carry `tabindex="-1"`, which made
  them interactive to the engine: pointer events theirs in grid mode,
  and nothing to select. A `tabindex` of -1 now marks no interactive
  element (cell-model.md). A grid drag over the popover selects its
  text in every engine; over the dialog, whose layer carries a
  backdrop, WebKit anchors the drag in the page's grid instead and
  selects the page's text — an engine difference of the backdrop
  layer's hit-testing, open, so the story asserts the popover's drag
  alone.
- The host observed only `class`, `style`, and the table spans, so a
  highlight moved by the keyboard — `data-highlighted` on the items,
  `aria-activedescendant` on the content, styled by Tailwind's
  `data-highlighted:` variant — painted only on the next relayout a
  pointer move or a scroll happened to bring. The host now observes
  the attributes that render (cell-model.md "Observation"), its own
  `data-mw-*` marks and host attributes filtered in the callback; leaf
  renderers declare no observed attributes any more (leaf-renderers.md).

### 3. The core

- `src/anchor.ts`: `placementArea(placement)` — Zag's twelve
  placements to `position-area` (`bottom-start` is `bottom
span-right`, `bottom-end` `bottom span-left`, `bottom` `bottom`,
  `right-start` `right span-bottom`, …); `anchorName(id)`; the
  fallbacks `flip-block, flip-inline, flip-block flip-inline`; the
  positioning options (`applyStyles: false`, `flip: false`, the
  listeners the probe found unneeded off); the props the trigger and
  the positioner gain, given the API's `open`, the placement asked,
  and a gutter in cells.
- `src/top-layer.ts`: `syncTopLayer(positioner, open)` — `showPopover`
  as the machine opens; on close, `hidePopover` once every animation
  under the positioner that ends (`getAnimations({ subtree: true })`,
  which flushes style, so the transitions the closed state starts are
  counted; one running forever or paused is not waited on) has
  finished, at once when none runs, a reopen cancelling
  the pending hide; idempotent, safe before the element is connected.
- `src/menu.ts`, `src/popover.ts`, `src/tooltip.ts`: `props(p)` and
  `api(zagApi, normalizeProps, p)` with `getTriggerProps`,
  `getPositionerProps`, and `getContentProps` (its `hidden` dropped;
  the menu's `getTriggerItemProps` too, the child's anchor) wrapped; `src/dialog.ts`: the positioner as the top-layer
  element carrying the `::backdrop`, `getBackdropProps` passed
  through untouched.
- Tests: the placement table; the props merged over Zag's, `style`
  and attributes both; `syncTopLayer` around a transition and without
  one, and across a reopen; a React smoke test — `useMachine` from
  `@zag-js/react`, the core over its `connect`, rendered with
  `react-dom/client` — asserting the trigger's and positioner's
  attributes in the DOM.

### 4. The vanilla path

- `src/vanilla.ts`: `mount(root, machine, connect, props, api)` —
  `VanillaMachine`, parts found by `data-part` under the root (items
  and groups by `data-value`), `spreadProps` re-applied on every
  state change, `syncTopLayer` after each; returns the API and a
  `destroy`. Per component, `menu(root, props)`, `dialog(root,
props)`, `popover(root, props)`, `tooltip(root, props)`. A submenu is
  a `data-part="trigger-item"` item in the parent followed by the
  child's root, `data-part="submenu"`: mounted as its own machine,
  linked by Zag's `setParent`/`setChild`.
- Tests: parts found and wired, a click opening the menu and the
  positioner shown, a submenu linked, `destroy` unwiring.

### 5. Stories and goldens

- `apps/storybook`: `@monowind/ui` as a devDependency;
  `ui.stories.ts` under `Packages / ui`, a story per component
  (the probe reversed the one-file-per-component plan), each story's
  markup wired by the vanilla path from its render (Lit's `ref`, once
  per element), the parts styled through the theme tokens.
- Per component, in every engine: open and close by pointer and
  keyboard; the positioner's cells under (beside, above) the trigger
  and its light element on them, over the page's later text; Escape
  and focus restore; roving focus, typeahead, and a submenu for the
  menu; the focus trap and the tinted page for the dialog; an exit on
  `data-state` holding the positioner to its end; a grid drag
  selecting the popover's text; the roles and ARIA states on the light
  DOM. The flip at the host's edge and the escape from a scroller are
  the positioning stories' (specs/ui.md "Testing"). A golden of each
  component open.

### 7. The framework packages

- `packages/ui-react`: `useMenu`, `useDialog`, `usePopover`,
  `useTooltip` — `props()`, `useMachine`, `connect()`, and a ref
  effect for `syncTopLayer`, the ref returned inside
  `getPositionerProps()`; `@zag-js/react` a dependency, `react` a
  peer; a node test through `react-dom`.
- `packages/ui-svelte`: `createMenu`, `createDialog`, `createPopover`,
  `createTooltip` in a `.svelte.ts` module — `useMachine` from
  `@zag-js/svelte`, the API a `$derived` behind a getter, the
  positioner an action that feeds `syncTopLayer`'s `$effect`;
  `svelte` a peer; the source published, typechecked with `tsc`.
- `packages/ui-vue`: `useMenu`, `useDialog`, `usePopover`,
  `useTooltip` — `useMachine` from `@zag-js/vue`, the API a
  `computed`, the positioner a template ref fed to `syncTopLayer` by a
  post-flush `watchEffect`; `vue` a peer; a node test through Vue's
  renderer.
- The React, Vue, and Svelte examples through them (`example-vue`
  new, its Vue plugin told `mono-wind` is a custom element); the
