# Themes initiative (`@monowind/themes` + core theme system)

Status: **implemented 2026-09-02.** Everything below landed, with
these settlements: themes are CLASS-SCOPED (`theme-<name>` on host or
wrapper) so multiple themes coexist per page; `blocks` shipped after
all, worn by the `bbs` theme; the c64 theme ships paletteless-font (BYO, license
trap confirmed) but full palette/borders; teletype uses a Courier
stack instead of a pack font. The play switcher toggles classes (all
theme css preloaded). First npm publish of `@monowind/themes` needs
the one-time manual step, then trusted publishing.

## Motivation

Make monowind look like the machines it evokes. Core gets a THEME
SYSTEM anyone can target (tokens, fonts, border glyph sets — a theme
is just CSS); `@monowind/themes` ships built-in themes modeled on
real systems: authentic palette, period font, and era-correct border
characters per theme.

## Research findings (2026-09-02)

- **Fonts, IBM/DOS side — solved**: the int10h "Ultimate Oldschool PC
  Font Pack" (https://int10h.org/oldschool-pc-fonts/) is CC BY-SA 4.0
  — redistributable with attribution. 200+ pixel-perfect charsets
  covering IBM VGA/EGA/CGA/MDA and dozens of other machines, in
  TrueType/WOFF. This is the backbone for every PC-era theme.
- **Fonts, Commodore side — licensing trap**: Style64's "C64 Pro
  Mono" (the canonical C64 TTF) forbids redistribution and hosting
  (https://style64.org/c64-truetype/license); Kreative Korp's Pet Me
  family is personal-use. Neither can ship on npm. Options, in order:
  an OFL/open PETSCII-coverage font (spike: kreativekorp/open-relay on
  GitHub hosts their FOSS fonts, e.g. Kreative Square covers Symbols
  for Legacy Computing), else the c64 theme ships palette + borders
  with a generic monospace fallback and documents the font as BYO.
- **Border characters are genuinely per-system**:
  - IBM PC (CP437): single AND double box drawing — the engine's
    current glyphs are already this world.
  - VT100/DEC terminals (Special Graphics set): single-line only —
    authentic terminal themes should downgrade `border-double`.
  - PETSCII: its own line set including ROUNDED corners — Unicode
    light arcs (╭╮╰╯) are the faithful stand-in.
  - Teletype/ASCII: `+ - |` only.
  - Chunky home-computer look: half/full blocks (▖▄▀█).
- **Palettes are well documented** (exact hexes verified at
  implementation from canonical sources): VGA 16-color, the C64 16
  (dark-blue screen / light-blue ink), green (P1) and amber (P3)
  phosphor monochromes, ZX Spectrum 15, Amiga Workbench 1.x 4-color.
- **Bitmap-font crispness**: period fonts render sharp only at
  integer multiples of their native size (VGA 8x16 → 16px, 32px…);
  themes pin `font-size` accordingly and document the constraint.

The public contract is specced in specs/theming.md (locked contract +
OPEN items, the leaf-renderers pattern); it becomes the source of
truth once implemented.

## Core: the theme system

PRINCIPLE: core stands alone. Everything here ships with working
defaults in `monowind` itself — default glyph set, `--mw-fg`/`--mw-bg`
system colors, ANSI token defaults — so the engine is fully functional
with zero `@monowind/*` packages; themes only override.

A theme is ONE CSS FILE, scoped by host class
(`mono-wind.theme-dos, .theme-dos mono-wind`) — two hosts on a page
can wear different themes, and all theme files can coexist.
Everything themable resolves through CSS the
engine already reads, plus one new engine hook:

1. **Token contract** (documented in a spec): `--mw-fg`, `--mw-bg`
   (exist) + the ANSI-16 `--mw-ansi-*` tokens. MOVE the ansi defaults
   from `@monowind/ascii`'s stylesheet into core's companion — they
   are terminal tokens, not ascii-art tokens; ascii keeps consuming
   them (non-breaking: same names, same defaults).
2. **Border glyph sets — the new engine hook**:
   `registerBorderGlyphs(name, set)` (registry idiom: normalized
   names, last-wins + warn, post-hoc registration relayouts).
   SCOPE HONESTLY: a set remaps the engine's FULL glyph vocabulary,
   not six corners — border styles per side, table-lattice junctions,
   gap-decoration `rule-*` separators and their junctions, multicol
   rules. Partial sets fall back to `default` per missing entry so
   authoring a set stays tractable. Selection is pure CSS: an
   inherited custom property (`--mw-border-glyphs: rounded`) read
   during measuring — a theme sets it on `mono-wind`, an element can
   override it locally (happy-dom/headless reads "" → `default`).
   The custom property carries only a NAME — glyph tables live in
   the JS registry; CSS never encodes glyphs.
   MIXING POLICY: a collapsed lattice resolves entirely with the
   TABLE's set — per-element overrides are for standalone boxes, and
   two sets never negotiate a shared junction. Built-in sets ship in
   core (`default`, `rounded`, `ascii`, `single-only`, `blocks`).
   FONT PAIRING: a set is only as good as the theme font's coverage
   of its characters — a missing glyph falls to the fallback font,
   whose different advance can drift the grid. Each theme pairs its
   set with a font verified to cover it (checked by the themed
   goldens).
3. **Fonts**: nothing new in the engine — `@font-face` +
   `font-family`/`font-size` on `mono-wind` (cell metrics are
   measured, any monospace works).

## `@monowind/themes` package

`themes/<name>.css` files (one import each) + redistributable fonts
(woff2 + per-font attribution, CC BY-SA notices) + README. No JS
except any custom glyph-set registration a theme needs (aim: none —
core's built-in sets should cover the launch themes).

Launch themes (all modeled on real systems):

| theme            | look                                     | font                                    | borders                       |
| ---------------- | ---------------------------------------- | --------------------------------------- | ----------------------------- |
| `dos`            | light gray on black, VGA 16 ANSI         | Px437 IBM VGA 8x16                      | default (CP437 single+double) |
| `dos-blue`       | Norton/Turbo Vision white+yellow on blue | Px437 IBM VGA 8x16                      | default, double-heavy         |
| `green-phosphor` | P1 green on black mono                   | Px437 or DEC-ish from the pack          | single-only                   |
| `amber`          | P3 amber on black mono                   | same family                             | single-only                   |
| `c64`            | light blue on dark blue, C64 16          | open PETSCII font or BYO (see research) | rounded                       |
| `teletype`       | ink on paper white                       | a typewriter-ish pack font              | ascii                         |

Stretch: `apple2` (40-col green, MouseText), `zx`, `amiga-workbench`.

**Palette remapping — the fidelity centerpiece.** Deliberately NOT
Tailwind `@theme` (build-time, global, Tailwind-build-only): Tailwind
v4 utilities compile to `var(--color-*)` references, so a theme
overrides those custom properties in plain CSS SCOPED to `mono-wind` —
runtime, CDN-compatible, live-switchable, and the surrounding page
keeps its normal palette. Each theme remaps the ENTIRE Tailwind
palette to its system's colors: every hue/shade quantized to the
nearest of the VGA 16 (or C64 16), and to phosphor brightness steps in
the monochromes — `text-red-500` inside `green-phosphor` renders the
right brightness of green. Mappings are GENERATED at theme-authoring
time (nearest-color in OKLAB, a build script in the themes package),
never hand-written. Escape hatches stay honest: arbitrary values
(`text-[#f00]`) bypass the vars and stay literal.

## Playground

Theme switcher in the toolbar: all theme css ships to the preview
iframe up front (small; fonts download on first use), and the
switcher just toggles the `theme-<name>` class on the preview host —
instant, no stylesheet churn. Persists as `?theme=` like the select
toggle. Theme CSS + fonts are
STAGED SAME-ORIGIN by copy-cdn.mjs (the ascii-fonts precedent) — the
switcher never depends on jsdelivr, so dev and unpublished states
work.

## Testing

- Engine: unit tests for glyph-set registration/resolution + a story
  asserting `--mw-border-glyphs` remaps borders per element; goldens
  for one themed story per glyph set.
- Themes: a story per theme (golden each); play smoke gains a theme
  round-trip assertion.
- Palette remap correctness: a story asserting `text-red-500` (and an
  opacity-modified color) compute to the theme's quantized values
  inside the host and stay STOCK outside it.
- Font crispness is visual-only — goldens at the pinned sizes.

## Release

Add `@monowind/themes` to the workspace (lockstep versions, patch
bumps). The first npm publish is MANUAL (trusted publishing cannot
precede package existence — the @monowind/ascii lesson), then
configure the trusted publisher and CI takes over. Any app build
script reaching into the new package must declare it
(scripts/check-workspace-deps.mjs enforces).
