# Layers implementation plan

Status: **implemented** (2026-09-13; every phase green, the stories'
goldens recorded). Spec: `layers.md` — normative; `cell-model.md`
"Animation", "Opacity", and "Pointer states"; the paint walk in
`plain-text.ts`, the DOM adapter in `paint.ts`; this plan only
sequences them. What shipped differently from the phases below:

- `Layer` carries only the `backdrop-filter`, which the companion locks
  on the light element; the box copies the other effects from the
  element's computed style once the light elements settle after a
  layout (`placeLayers: false` in the layout's paint, then
  `syncLayers`), since the measure-pass values are the measuring-time
  box's. The companion's leading lift moved from `translate` to `top`
  (flow children `relative` with their insets pinned) so `translate`
  stays the author's.
- A layer buffers its puts and lays them into a `cellStore` of its
  extent at close; `renderGrids` returns `{ store, layers }`, and
  `PaintedLayer` carries the root's `box`. The ancestors' clips travel
  the walk as one rectangle (`Clip`), which the lattice and the layers
  share.
- The node is a `<div class="layer">` box holding a `<pre class="grid">`,
  tracked per container in a `LayerSet` and placed in px of the
  measured cell; the pointer's inverse is composed from the placed
  values (`inverseOf`), and `#cellAt` returns the grid hit with it.
- `SAMPLED_TRANSITION` gained `transform`, `translate`, `rotate`,
  `scale`, `filter`; `backdrop-filter` snaps (spec deviation 6).
- The transition and the drags are the `!dev` stories `LayerTransition`
  and `LayerSelection`; the grid-mode drag inside a layer is the
  `test-selection--layer` goldens; the README got a clause in its
  feature paragraph.

## Shape

A layer root's subtree paints into a grid of its own — a `<pre>`
beside the main one, transformed and filtered natively — while the
model (the transcript, selection, hit-testing) keeps every cell at its
layout position. So the split lives in two places: the walk, which
opens a layer per root and tracks its extent, and the adapter, which
gives each layer a node, its geometry, and the copied properties. The
transcript composites the layers back over the main grid, so
`renderPlainText` and the text-mode selection see one grid, as the
spec asks.

## Phases (each ends green: `pnpm check` + the visual sweep)

### 1. Reading

- `types.ts`: `CellStyle.layer: Layer | null` — `{ transform,
translate, rotate, scale, origin, filter }` as computed strings,
  `origin` in px of the border box. Null unless one of them is set
  (`transform` other than `none`, the individual properties other
  than `none`, `filter` other than `none`).
- `style.ts`: `readLayer(cs)`. Nothing to lock in the companion: the
  light element keeps its transform for native hit-testing (locked
  decision), its ink is transparent already.
- Tests: `layer.test.ts` reads through `readCellStyle` with inline
  literals (happy-dom keeps them): each property alone, all at once,
  `none` everywhere → null.

### 2. The paint split

- `plain-text.ts`: the cell store `renderGrids` builds (grid, paints,
  owners, the put with wide-cluster release) becomes a function
  `cellStore(width, height, x0, y0)`; a layer's store is sparse
  (a `Map` keyed by cell, bounds tracked on every put) and
  materializes to a rectangle after the subtree. `walk`, at a node
  whose `style.layer` is set, opens a layer: a new store whose put the
  root's own decorations and children receive, the parent's put left
  alone; after the subtree the layer is closed — `{ node, x, y,
width, height, grid, paints, parent }` pushed to `layers`, in paint
  order, nested layers noting their parent. `renderGrids` returns
  `{ grid, paints, layers }`.
- `renderPlainText`: layers composited back onto the main grid at
  their layout positions, in order (a later layer over an earlier
  one, glyphs and paints alike), so the transcript and every node test
  see one grid. `renderGridRows` (the adapter's) returns the main
  rows and the layers' rows separately.
- `paint.ts`: `paintGrid`'s body becomes `paintRows(target, rows,
cells, options)` — the signature, structure diff, and selection
  save/restore per target as today — called for the main grid and for
  each layer's node. Layer nodes: a `<pre class="grid">` per layer
  root element (`WeakMap<Element, HTMLPreElement>`), appended to the
  viewport or to the parent layer's node in paint order, removed when
  a pass paints it no more; positioned at the layer's origin in cells
  (`left`/`top` in `--mw-cw`/`--mw-ch`), sized to its extent, and
  carrying the copied `transform`, `translate`, `rotate`, `scale`,
  `filter`, and `transform-origin` shifted by the extent's offset from
  the border box. `#grid` keeps its id; the shadow stylesheet's grid
  rules move to `.grid` so layers share them; a layer adds
  `user-select: contain` and `position: absolute`.
- `element.ts`: passes the viewport to the paint; `applyModes` and
  the theme nudge unaffected (layers are inside the host's shadow).
- Tests (`layer.test.ts`, node level): a transformed box's cells absent
  from the main grid's rows and present in its layer at the layer's
  origin; the extent grown by an overflowing child and by an outer
  shadow; nested layers with the inner's parent set; the transcript
  unchanged with and without the transform; a layer inside a scroll
  container at its scrolled cells; a scroll container as a layer root
  painting its bars inside. Storybook: the adapter's node per layer,
  its geometry and copied properties equal to the light element's.

### 3. Hit-testing and selection through layers

- `element.ts` `#cellAt`: the painted layers' nodes, innermost first,
  are tested by geometry — the client point mapped through the
  inverse of each node's current `transform` matrix (a `DOMMatrix`
  from `getComputedStyle`, about the node's origin, nested layers
  composed) — and the first whose untransformed box contains the
  point gives the cell (its origin plus the local cell); otherwise the
  main grid does. The result stays in main-grid coordinates, so
  `hitStack`, the pointer states, and the text-mode gestures work
  unchanged.
- Grid-mode gestures (`gridOffsetAt`, `paintedCell`, the anchors in
  `#gridOffsetAt`) take the target under the cell: the innermost layer
  whose extent covers it, else `#grid`, with the cell made local.
- Tests: Storybook plays — a text-mode drag across a rotated badge
  selects the glyphs under the pointer; a grid-mode drag inside a
  scaled layer stays inside it; `selection.spec.ts` gains a
  three-engine check that the layer's box and the light element's box
  agree.

### 4. Sampled transitions

- `SAMPLED_TRANSITION` gains `transform`, `translate`, `rotate`,
  `scale`, `filter`. A running transition of one of those alone does
  not relayout per frame: the sampling loop re-copies the computed
  properties onto the layer nodes (`#syncLayers`) and relayouts once at
  the end, as the loop settles today; a color or opacity transition
  running at the same time keeps the per-frame relayout.
- Tests: a Storybook play with `transition-transform` on a scaled
  dialog — the layer's transform equals the light element's mid-way
  and at rest; a node test that a layer style read mid-transition
  carries the interpolated matrix (happy-dom has no transitions; the
  read is the unit).

### 5. Stories and docs

- `effects.stories.ts` "Layers": a scaled dialog with a transition and
  a native button inside (clickable where shown), a rotated badge, a
  `blur` panel and a `grayscale` one, a layer inside a scroll
  container, nested layers; goldens of the resting states.
- `cell-model.md` "Animation" lists the new sampled properties and
  gains an "Effects" pointer to `layers.md`; the README gains a short
  "Transforms and filters" section; `layers.md` status implemented,
  its deviations checked against what landed.
