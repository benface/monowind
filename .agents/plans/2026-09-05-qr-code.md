# `<mono-qr>` implementation plan

Status: **implemented** (2026-09-05), phases 1–4 and the docs of
phase 5; its first-time manual publish is the user's, before the next
release. Spec:
`.agents/specs/qr-code.md` (normative; this plan only sequences it).
Ships as the new `@monowind/qr-code` package in 0.2.9, at the same
version number as the other packages (AGENTS.md "Releasing"). Found on the way: the test decoder needs four modules
of quiet zone around a code, so the decode fixture pads `px-4 py-2`, and the
playground code sits in a `px-2 py-1` box, the two-module zone most
phones read; the fixture covers the shipped fonts only; `aspect`
generalized past 2 (half blocks repeated per module) and below 0.5
(more rows) on review; then the `quiet` attribute and `frame()` were
DROPPED (the user: padding under another name) — the rows are the
bare symbol and the quiet zone is `p-*`, opt-in, nothing by default;
the phases below describe the first design.

## Phases (each ends green: `pnpm check` + the visual sweep)

### 1. Core: the three glyph roles

- `GlyphTable` (glyphs.ts) gains optional `qrFull`, `qrUpper`,
  `qrLower`; the built-in `ascii` set's `solid` table gets
  `qrFull: "#"` (dropped after the decode spec: a `#` in Courier New
  is too sparse to scan, so no built-in names a role — see the spec);
  `glyphSetFor` joins the package exports (index.ts)
  AND the CDN global (cdn.ts lists the extension API by name —
  verified: only `registerLeafRenderer` and `invalidateLeaves` ride it
  today). No defaults in core.
- Tests (`glyphs.test.ts`): no built-in set carries any of the
  three; `glyphSetFor` reaches them.
- leaf-renderers.md names the second consumer; the core README's
  companion list gains the package.

### 2. The package: `packages/qr-code`

- Layout mirrors `packages/ascii` without fonts: `package.json`
  (`@monowind/qr-code`, `monowind` as `workspace:^` peer and dev
  dependency, `qr` as the dependency, same `exports`/`publishConfig`
  src→dist swap, `sideEffects` on the entry, `prepack` copying the
  LICENSE), `tsconfig.json`, `tsconfig.build.json`, `vite.config.ts`,
  `vite.cdn.config.ts` (IIFE `monowindQr`, `monowind` external on the
  shared global), `README.md`.
- The `qr` package as the one runtime dependency (the user's
  suggestion, replacing a vendored encoder and a separate test
  decoder): `encodeQR(value, "raw", { ecc, border: 1, version })`,
  sliced of its border; "Capacity overflow" is the overflow error; a
  pinned `version` with a higher `ecc` is the level boost.
- `src/render.ts` — pure, DOM-free, unit-tested:
  - `encode(value, level): boolean[][] | null` — the module matrix,
    null when the value exceeds version 40 at that level.
  - `frame(matrix, quiet)` adds the quiet zone; `scaleUp(matrix, n)`
    repeats every module `n × n`.
  - `pack(matrix, aspect, glyphs)` → `string[]` rows: aspect 2 pairs
    module rows into `▀ ▄ █` and space (an odd count leaves the last
    lower half light); aspect 1 one `█` per module; aspect 0.5 two
    stacked; a glyph set with `qrFull` but not both halves at aspect 2
    draws `qrFull` twice per module, one cell row per module row.
  - `snapAspect(ratio)`: `≥ 1.5 → 2`, `≤ 0.75 → 0.5`, else `1`.
  - `resolveGlyphs(set)`: the three roles from a `BorderGlyphSet`'s
    `solid` table — each role falls back to its default (`█ ▀ ▄`);
    halves exist when the set declares both or neither, so a set that
    declares `qrFull` alone has none.
  - Memoized: the matrix per `(value, level)` and the rows per
    `(matrix, quiet, scale, aspect, glyphs)`, one entry each per
    element, since `render` runs every layout pass and a long value's
    encoding (Reed–Solomon plus eight mask trials) is milliseconds.
- `src/index.ts` — `MonoQrElement`, `defineMonoQr()`, and the
  registration: tag `mono-qr`, `render`, `selectionTarget`, and the
  observed attributes `level`, `quiet`, `aspect`, `scale`:
  - `render(el)`: the value is `el.textContent` with collapsible
    whitespace trimmed at the edges (the ascii element's rule, so a
    leading `&nbsp;` is data); attributes parsed with the spec's
    fallbacks; `aspect` from the attribute or the snapped ratio of
    the `--mw-ch` and `--mw-cw` custom properties read off `el`'s
    computed style (inherited from the host), `2` when unmeasured or
    without `getComputedStyle` (a DOM-less Node run). Verified:
    happy-dom does not inherit custom properties into a descendant's
    computed style, so the element tests pass `aspect` explicitly (the
    auto path reads `2` there) and the Storybook story asserts auto in
    real browsers;
    the glyph set from `glyphSetFor(--mw-border-glyphs)`; a too-long
    value warns once per element and renders no rows; element
    children warn once and are ignored, as in the ascii element.
  - The shadow root holds the transparent transcript `<pre id="mirror">`
    (the packed rows, synced per render like the ascii element's) and
    the visually hidden `<slot>` for the value text; the same shadow
    CSS as the ascii element (transparent `::selection`, the `.alt`
    hiding).
  - `src/cdn.ts`: registers on load and merges `{ qr: { version } }`
    into the shared `monowind` global.
- Tests (`packages/qr-code/test`, happy-dom):
  - `render.test.ts`: `encode` against fixed vectors (a short
    numeric, an alphanumeric, a URL, at each of L/M/Q/H → the
    expected version; the level boost visible as the reported level);
    `frame` and `scaleUp` on a 3 × 3 matrix; `pack` at aspects 2, 1,
    0.5 over an odd- and an even-row matrix, with the default glyphs,
    the ascii fallback, and a custom set; `snapAspect` at the
    thresholds; `resolveGlyphs` on the three declaration shapes.
  - `decode.test.ts`: every `pack` output rasterized from its glyphs
    at 6 px per module (a cell is 6 × 12 px at aspect 2, its halves
    split; 6 × 6 at aspect 1; 6 × 12 as two cells at 0.5) inside an
    eight-module quiet zone and decoded with `qr/decode.js` — every
    aspect, dark on light and light on dark, all four levels, `scale`
    2, a long value at version 10+, and the `##` fallback.
  - `element.test.ts`: `<mono-qr>` inside a `<mono-wind>` under
    `renderPlainText` — the row count and width for a known value at
    default attributes (29 × 15 for a version-1 value); each attribute
    changes the output as specified (`level`, `quiet="2"`,
    `quiet="0"`, `aspect="1"`, `aspect="0.5"`, `aspect="1.7"` snapping
    to 2, `scale="2"`, `scale="3"`); an invalid attribute reads as the
    default; an empty element renders no rows; element children warn
    once; a too-long value warns once and renders nothing; the
    transcript equals the rows; `selectionTarget` returns it.

### 3. Storybook

- `apps/storybook` depends on the package (`workspace:^`); `preview.ts`
  imports it beside the ascii package.
- `stories/qr.stories.ts`, `Components / mono-qr`: a default code, one
  with `quiet="2"`, `scale="2"`, `aspect="1"`, `aspect="0.5"`, one in
  `bg-white text-black` on the dark theme, one with a registered
  full-only set (the `##` fallback), all in the sweep; a `Test / QR` story (hidden)
  asserting the grid rows equal the transcript, a text-mode drag
  selects characters of the transcript, a double-click a row, a
  triple-click all of it, the copy pastes as block characters, an
  attribute change re-renders, and the value text stays in the light
  DOM for assistive technology.
- `visual/qr.spec.ts`: screenshot each code of the hidden `Test / QR
/ Fonts` fixture per engine and decode it with `qr/decode.js` from
  the PNG (`pngjs`, dev dependency) — the fonts the repo ships, the
  preview's JetBrains Mono and the `dos` theme's VGA face, each padded
  `px-4 py-2` (the decoder's minimum) — asserting the decoded text.
  Goldens for the visible stories like every other.

### 4. Playground

- `copy-cdn.mjs` copies the package's `dist/cdn.js` as `qr-cdn.js`;
  `index.html` and the preview `srcdoc` load it after `ascii-cdn.js`.
- The default sample gets a code at the bottom of the scroller, under
  the columns: a centered line inviting the reader to scan for the
  online edition, then a centered
  `<mono-qr quiet="2">https://play.monowind.benface.com</mono-qr>`.
  `smoke.test.mjs` asserts `qrRendered` (rows in the grid under the
  element) beside `asciiRendered`.

### 5. Release and docs

- `release.yml` publishes it with the others (`pnpm -r publish`
  already does) — except the FIRST time: npm's trusted publishing is
  configured per existing package, so the user publishes the package
  once by hand (`pnpm publish` in `packages/qr-code` with an npm
  login), then lists the workflow as its trusted publisher; the
  workflow takes over from the next tag. The package's version matches
  the others.
- Root README: companion list and a short example beside the ascii
  one; core README companion list; AGENTS.md if it lists packages.
- The spec's status → implemented; memory.
